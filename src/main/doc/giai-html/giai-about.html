About The Guided Intelligence Architecture Implementation - Project GiAI v1.1

The goal of project GiAI is to provide an initial implementation of the core tools and technologies that an Artificial Intelligence of any sort would require in order to be able to transform models of the information it was going to have to store and access into efficient application code in Phase I, be able to calculate statistics and fire confidence-based events to trigger application responses to those conditions in Phase II, and the build-out and training in Phase III.

GiAI: Phase I - Yorkton Code Fractal - Project YCF

The goal of Phase I was to develop what ended up being named the Yorkton Code Fractal in the end. YCF 3.1 provides the tools and technology to apply a knowledge base description of how to transform a business model into application source code, and to execute those transformations in mere seconds to a minute or few on modern hardware without relying on inefficient LLM toolchains and technologies.

GiAI: Phase II - GiAI Core

The primary goal of GiAI Core is to provide a framework for evaluating statistics by filter group over the object interfaces and collections/sets/arrays/streams provided as IO operatives and data accessors when the application code produced by Yorkton Code Fractal 3.1 has been built and run as an available service. This layer of technology is the heart of the GiAI 1.1 project, and comprised of dual GPLv3/Commercial licensed implementations in the giai-core module, and as tool-bound via a number of GiAI service interface subinterface implementations where each tool defines a service interface for creating an instance for executing the tool, executing the tool over a set of code with specific arguments to the tool, packaging the outputs from the tool for delivery, and installing the delivery artifacts.

Key technologies that will be implemented by GiAI 1.1 include message and event propagation and consumption interfaces and implementations for various virtual pipe formats that need to be supported in a hybrid server-node/web-service/web-client environment, while ensuring appropriate security, integrity, atomicity and repeatability requirements are met by each of the three technology implementation technology and their subclass specializations.

Where applicable, new fractal code production rules will be crafted for execution by the Yorkton Code Fractal 3.1 runtime by subclassing the IGiAI interface specifications and implementations to provide statistics evaluation verbs bound to a Next Generation GiAI v1.1 layer that builds and enhances the fundamental YCF 3.1 produced service implementation code.

GiAI: Phase III - Performance Enhancements and Tuning of the GiAI Curiosity Engine

The final Phase III task is to improve the performance of the GiAI "Curiosity" subsystems through the application of some dynamic JPA code approaches that I know are feasible, and through a combination of event propagation clarifications and filters with the default service implementations required to automate their task processing. Even if I was never aware of the nuts and bolts details of exactly how to go about setting up the dynamic JPA, once you know something can be done, the hard part is over because you know you're no longer chasing a dream, but a potentially-hard-to-achieve reality. It is then just a matter of time and persistent debugging until you achieve victory over the machine and have automated the task at hand. I've seen dynamic OSQL used with JPA before, and I've definitely done a lot of event propagation and filtering over the many decades of my career.
